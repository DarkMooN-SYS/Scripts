# MooN | HUB

`main.lua` is generated by `build.ps1`. Edit source modules and rebuild from this folder.

- `UI/`: reusable menu, dashboard, and Discord authorization UI
- `Games/<PlaceId>/Config.lua`: experience metadata
- `Games/<PlaceId>/init.lua`: per-experience entry point
- `Games/<PlaceId>/Features.lua`: current feature implementation

`build.ps1` bundles the selected modules into one `main.lua`; runtime disk access is not required. Add another experience by creating its PlaceId folder with its own `Config.lua`, `init.lua`, and feature modules, then add that bundle entry to `build.ps1`.

Discord authorization uses `https://moonhub.freesrv.com/login/<userId>` and polls `https://moonhub.freesrv.com/check?userid=<userId>`. This client flow requires an HTTP request function from the runtime. For production authentication, verify authorization on the experience server.

## Client bug reports

`UI/Debug.lua` keeps the most recent 40 captured menu callback errors in memory. Errors are deduplicated for 60 seconds and include the current PlaceId, feature label, message, and traceback. Read the local ring buffer with `menu.Debug.GetCache()` or report a caught error with `menu.Debug.Report(feature, message, traceback)`. The wrappers on menu toggles, buttons, and sliders capture callback failures automatically.

Discord delivery is server-only. Install `Server/DebugWebhook.server.lua` as a Script under `ServerScriptService` in each experience you own. In Creator Hub, create a secret named `MooNHubDiscordWebhook` whose value is the FULL rotated webhook URL; enable HTTP requests in Experience Settings → Security. The server validates payload size, rate-limits each player, deduplicates reports, and posts experience name, PlaceId, GameId, place version, feature, and traceback. It does not include the player's name or UserId. Enable/validate this only in your own experience; the client relay cannot reach Discord unless that experience contains the server script. Rebuild `main.lua` after source edits.
